Improve an agent

The library only gets better if people work on it. Here is how to take a piece, do it well, and hand it back.

Ways to help

Pick the job that fits your time.

Every agent page lists what is unresolved. Start there.

  • Review a draft specification: confirm the purpose, inputs, outputs and side effects.
  • Test an agent with synthetic fixtures and record exactly what ran.
  • Port it to Plain Python, Pydantic AI, CrewAI or LangGraph.
  • Extend it: add a tool, a guardrail, an evaluation, or a failure test.
  • Fix a source problem such as a broken connection or a missing credential note.
01

Choose

Browse the library. Small agents (up to 6 nodes) make good first picks.

02

Claim

Open a GitHub issue on the Agents repository saying which agent and which piece you are taking.

03

Build

Follow the architecture and contribution contract. Add your work beside the existing implementation; do not duplicate the agent.

04

Show evidence

Label results honestly and send a pull request.

Ground rules

Evidence means what it says.

A planned folder or an untested prompt is not a working implementation. Use the status labels: source-available, planned, fixture-tested (local deterministic tests, run and recorded) and live-tested (needs a dated, scoped receipt).

Never commit credentials or private data. Test with synthetic inputs. Keep each source's original attribution and license; curation is not a claim of authorship.
